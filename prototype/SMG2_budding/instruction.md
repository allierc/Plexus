# SMG2 Branching Morphogenesis — Scientific Agent Instructions

## Mission
Build a **Plexus FORWARD MODEL** of submandibular-gland (SMG) branching morphogenesis that is a
**phenomenological understanding — NOT a per-cell fit of the data.** The goal is to discover which
operator compositions reproduce the *real-data phenomenology* of the SMG2 movie:

  1. **collective cell migration** (coherent tissue flow, PIV-measurable),
  2. **a growth-rate law** (localized proliferation that inflates the tissue), and
  3. the **emergent topology** these produce — a main duct that **buds** and **branches**.

The scientific object is the mapping **operators + couplings → migration + growth → topology**. A
finding is *which mechanism caused a phenomenon* (a bud, a branch, coherent flow), tagged and
regime-noted — never a numeric optimum. Training/each run is an experiment answering ONE falsifiable
hypothesis. **We reproduce the PHENOMENOLOGY (trends, spatial organization, the budding trajectory),
scored SMOOTHLY against the target (see `knowledge.md`), not the exact per-cell trajectory.**

## The TARGET (real-data observables — the smooth constraint)
The real SMG2 data has been analyzed into the reference the model must reproduce
(`real_data_montage.png`, generated by `real_data_montage.py`; see `knowledge.md` for the smooth
target curve). Three observable families, each over the run:
  - **topology** (`smg_topo.py`): `n_bud` rises monotonically ~4→~20, `n_branch` ~2→3, `n_tube`≡1.
  - **growth** : proliferation-source field (continuity residual `∂ρ/∂t + ∇·(ρv)`), positive and
    **localized at bud tips**; net population growth ~1.3× over the run.
  - **migration** (PIV, dense optical flow): coherent tissue flow, nonzero polar order, correlation
    length of a few cell diameters, tip-directed streaming.
The loop's job is to make the forward model's OWN analyzed observables approach these — smoothly.

## HARD RULES (bright lines — inherited from the embryo loop)
- **NO dedicated "bud"/"branch"/"tube" operator.** Budding and branching MUST EMERGE from composing
  primitives (`cell_grow` gated by a morphogen field + mechanics + migration + tension). An explicit
  branch operator is a FAIL.
- **R1 Minimal mechanism first** — exhaust coupling-strength / density / stiffness changes in the
  current operators before ADDING an operator.
- **R2 No collapse** — cells never stack (min cell–cell distance ≥ `r0`); if collapse appears, first
  reduce the mechanical feedback gain, do not just crank `repel`.
- **R3 One new operator family per batch** (keep batches interpretable).
- **R4 Always a control** — every batch has ≥1 ablation slot removing the operator the hypothesis
  credits, so attribution is causal.
- **Phenomenology, not fit** — never add machinery whose only justification is matching a number; it
  must correspond to a biological mechanism (growth, motility, signaling, adhesion, tension).

## Staged ladder (advance a rung ONLY when its gate is met with no hard failure)
- **S1 — tissue substrate.** Cells cohere into a confluent 3D epithelial mass (adhesion/tension +
  `repel`), 0 collapse, stable. *Gate: stable body, collapsed=0.*
- **S2 — collective migration.** Motility-driven unjamming + flocking (`polar_align`+`motility`+`repel`,
  shape-index fluidization) yields coherent flow whose PIV statistics resemble the real data.
  *Gate: polar_order & correlation-length in the real-data range, not jammed.*
- **S3 — growth law.** Continuous `cell_grow` (+`cell_divide` to repopulate) inflates the tissue at the
  target net rate. *Gate: smooth volume/number growth, tissue intact.*
- **S4 — morphogen patterning.** A Turing / reaction–diffusion field (`deposit`+`diffuse`+`decay` or
  `reaction_diffusion`) forms a stable spatial pattern on the growing tissue. *Gate: persistent pattern.*
- **S5 — BUD.** Morphogen-GATED localized `cell_grow` produces a reproducible protrusion that rounds by
  tension. *Gate: one emergent bud, body intact.*
- **S6 — BRN.** A minimal FEEDBACK law (stress- or curvature-dependent growth, tip inhibition, growth
  competition) turns one tip into MULTIPLE buds — the **budding trajectory rises like the real data.**
  *Gate: reproducible bifurcation, `n_bud` trajectory tracks the target within tolerance.*
- **S7 — INTEGRATE.** One gland that simultaneously migrates, grows, and reproduces the full topology
  trajectory + growth-localization + PIV. *Gate: all three observable families within smooth target.*

Write the target rung to `current_stage.txt` each batch; ≤10 batches per rung, then adopt best clean
point and advance.

## SCORECARD — decide on NUMBERS (see `smg_scorecard.py`)
Every slot writes `scorecard.json` (+ `scorecard.png`) via `smg_scorecard.py`, computed at
5/25/50/75/100% of the run:
- **topology agreement** — `n_bud`/`n_branch`/`n_tube` vs the target trajectory (bud ±20%, branch ±1,
  tube exact); `topo_accuracy`.
- **temporal consistency** — `bud_trend` (want +), `bud_growth_ratio` (~5), `branch_monotonic`,
  `count_jitter`, `tube_stability`.
- **geometric fidelity** — how well the primitive model explains the cloud (`coverage`, `chamfer`).
- **migration** — `polar_order`, `speed`, `corr_length_xi`, `net_circulation` (from PIV).
- **growth** — net growth ratio, `growth_tip_localization` (does proliferation sit at bud tips?).
Read the numbers AND their 5-point trajectory; the mp4/montage only PROPOSE a hypothesis — the
scorecard DECIDES.

## QUANTITATIVE REPORT PROTOCOL (mandatory in every `analysis.md` entry)
Pair every visual claim with scorecard support, e.g.:
> visual: "a second bud appears mid-run"
> quantitative: topology.n_bud 3→5 over 50→100%; growth localized at the new tip (tip_localization 0.34→0.61)
A claim with no number is an opinion, not a finding.

## `[established]` gate
Promote a mechanism to `[established]` only with ≥3 seeds AND |Δ| > 2·SD vs its ablation control
(report mean±SD). One run + a movie is `[open]`.

## Per-batch cycle (do ALL, in order; auto-update files)
1. **Observe** the previous montage + each slot's scorecard/metrics (numbers, not the movie).
2. **Append** a dated `## Batch N` to `analysis.md` (quantitative report protocol).
3. **Distill** `knowledge.md` — merge findings tagged `[established]/[open]/[rejected]/[engineering]`.
4. **Hypothesize** ONE predictive statement for this batch.
5. **Design 8 slots** into `smg_slots.md` (~4 exploit · 3 explore · 1 control), one lever per slot.
6. **Predict** each slot's observable change; after results, **verify** supported/falsified.
