\section{What this is}

\code{discovery\_okuda} held the 3D active vertex model, reaction--diffusion on the cell graph, the
junction and medioapical myosin pools, and the whole basement-membrane / extracellular-matrix stack:
52 registered operator names across 21 files, and behind them \code{log/okuda} and
\code{log/okuda\_ECM}. None of it was in the framework \code{paper/plexus2.tex} describes. The core's
own \code{src/plexus/operators/} carried 43 names in 45 one-operator files, and not one mesh or
chemistry operator among them.

This note is the record of moving that vocabulary into the core, written as each phase landed rather
than summarised afterwards. Its structure follows the paper's four parts --- mechanism, equations and
symbols, the Plexus2 container, gates --- with one section per phase, and its gate tables are
generated from the run record by \code{tools/promotion\_note.py} rather than transcribed.

\paragraph{The two things that had to be true.} A promotion of this size is only checkable if it can
be shown to change nothing. Two gates run on every phase.

\begin{enumerate}
\item \textbf{The twin run.} The spec is run in okuda \emph{first}, and its twin is run in the
  codebase; previous okuda results are never the reference, because okuda is still moving. Both
  sides are submitted \emph{together}, as two \code{bsub} jobs on \code{gpu\_l4}, and the comparison
  is array by array, bit for bit, reduced to one sha1 per side.
\item \textbf{The okuda\_ECM gates 00--04}, each assigned to the phase that enables it, each with a
  table of thresholds declared \emph{before} the promoted run. \S\ref{sec:gates}.
\end{enumerate}

\section{Phase 0 --- the engine}

\subsection{The half-edge mesh becomes an engine concept}

A closed cellular surface is stored as a flat half-edge table: three parallel \code{int64} arrays
\code{E\_srce}, \code{E\_trgt}, \code{E\_face}, plus the counts \code{nF} (faces $=$ cells) and
\code{Nv}. Face $f$'s ring is recovered by walking the table and appending \code{E\_srce[k]} for
every $k$ with \code{E\_face[k] == f}, \emph{in table order}. That ordering \emph{is} the geometry:
\code{rings\_from\_flat\_3d} never reads \code{E\_trgt}, never sorts and never validates, so a sort,
a compaction, or a scatter-into-reservoir by any future writer produces garbage rings in silence.

Before this promotion the table was a private attribute one operator invented ---
\code{grep -rn "\_mesh" src/plexus/} returned nothing at all --- while roughly forty consumers read
it: the chemistry, the mechanics, the T1s, the cross-scale contact operators, the recorder, the
salvage, the instrument's fingerprint, the renderers. A spec could schedule \code{cell\_mechanics}
without \code{mesh\_seed} and die of \code{AttributeError} from inside an autograd pass.

It is now declared and allocated:

\begin{center}\small
\begin{tabular}{@{}ll@{}}\toprule
\code{sets: \{vertex: \{mesh: half\_edge, cell\_set: cell\}\}} & the declaration\\
\code{plexus.models.mesh.MeshTable} & the table, a \code{dict} subclass\\
\code{plexus.models.topology} & its algorithms (rings, edge split, face division)\\
\code{engine.\_build\_mesh} & allocates an \emph{empty} table in \code{build}'s pass 1\\
\code{seed\_mesh} & \emph{fills} it, rather than rebinding a new one\\
\bottomrule
\end{tabular}
\end{center}

\paragraph{Why it subclasses \code{dict}, and this is not a style choice.}
\code{discovery\_okuda/instrument.py:43} reads \code{if isinstance(m, dict):}. That is the acted
ledger --- the thing that decides whether an operator \emph{did anything} --- wrapped in a bare
\code{except Exception: return ()}. A \code{MutableMapping} that is not a \code{dict} subclass fails
that test silently, the fingerprint collapses to \code{()}, and every operator whose only effect is
on the mesh (\code{cell\_grow} writing \code{V0f}, \code{cell\_divide} changing \code{nF},
\code{junction\_myosin} writing \code{myo}) scores zero acts. The campaign then stamps
\code{valid\_evidence: False} on runs that were fine.

\paragraph{And the namespace stays open, deliberately.} Five keys are reserved; everything else is an
extension namespace, because three live mechanisms depend on a name being \emph{absent}:
\code{cell\_shape\_probe} publishes a field and then deletes it (absent means ``no cell dies'';
zero-filled would mean ``kill everything''), \code{ecm\_gate\_growth}'s entire entry condition is
\code{'mg\_scale' in m}, and the apoptosis discriminator resolves whatever name its spec gives it.

\paragraph{The carry was written four times.} Permuting every per-face array through \code{keep} is
one operation, and it existed in \code{cell\_divide}, in \code{cell\_die}, in
\code{\_carry\_face\_state} and in \code{edge\_flip} --- and the fourth copy silently omitted the
medioapical myosin, because a per-face state added by one operator has to be known to every topology
operator and that one did not get the memo. It is now \code{MeshTable.reindex\_faces}, and the
renumber of the paired \emph{cell} set is \code{Hierarchy.renumber\_set}, which moves all four stores
the engine keeps per set. The fourth, \code{\_delta\_blocks}, is the one both hand-rolled versions
missed: they guarded on \code{isinstance(key, tuple)} while \code{add\_delta} keys by level
\emph{name}. It is inert today only because \code{chem} happens to be the cell set's coordinate
block, so its deltas travel in \code{\_delta}; a second \code{first\_order} block on that set makes
it live.

\subsection{The recorder keeps the topology}

\code{topo\_record} appended its history \emph{inside} the mesh table
(\code{m.setdefault("hist", [])}), so the structure the engine now owns grew without bound for the
length of the run and every consumer walked past a list of every frame it had ever had. The engine
records it: one \code{MeshTable.snapshot()} per recorded row, written to both zarr and npz as a
ragged store with \emph{no pickle} --- the three half-edge columns concatenated, plus row offsets,
plus \code{nF}/\code{Nv} per row. Euler now computes off the core's own trajectory file,
\[
  V - E + F \;=\; \mathtt{Nv}[t] \;-\; \tfrac{1}{2}\big(\mathtt{off}[t{+}1] - \mathtt{off}[t]\big)
  \;+\; \mathtt{nF}[t] \;=\; 2 ,
\]
which is what gate~00's closed-form row needs and what \code{topo\_record} could not give it.

\subsection{Two bugs that destroyed finished work}

\begin{itemize}
\item \code{Group.create\_dataset(name, data=...)} is the zarr-2 spelling. zarr~3 kept the method,
  deprecated it, and made \code{shape} a \emph{required} keyword, so every core generation on the
  cluster (zarr 3.1.5) died \emph{after} the whole simulation had run and \emph{before} the npz was
  written --- 25 minutes of GPU, an empty \code{simulation.zarr}, no trajectory. The devcontainer
  has zarr 2.18.7, which is why it never appeared in development.
\item The npz writer put \code{d["pos"]} in unconditionally. A mesh model's \code{cell} set has no
  \code{pos} block at all --- it carries \code{chem}, \code{cen}, \code{area} --- so \code{None} went
  in as a 0-d \emph{object} array and every read of the file died on \code{allow\_pickle}. Worse, the
  recorded blocks were not written at all: a reaction--diffusion run wrote a trajectory with no
  reaction in it.
\end{itemize}

\subsection{325 of 461 specs did not load}

Not ``would eventually fail'': \code{ValueError: operator 'seed\_mesh' not in registry}, for every
\code{r0*} the campaign had ever written. The specs had been migrated to the post-seed-refactor
\code{seed\_<noun>} convention --- the one core already uses for \code{seed\_from\_segmentation} ---
and the okuda classes had not, so the corpus split 324/137 across two spellings of one operator and
the larger half was dead. Both spellings resolve now: canonical \code{seed\_mesh} and
\code{seed\_cell\_chem}, aliases \code{mesh\_seed} and \code{cell\_chem\_seed}. 460 of 461 load; the
one that does not names \code{morphogen\_growth\_3d}, which is stale in a different way and is
recorded rather than guessed at.

\section{Phases A--D --- the operators}

\code{tools/group\_operators.py} moved them, and the choice to write a script rather than edit by
hand is the reason bit-equality is a reachable claim across 3{,}800 lines. It hoists each source's
imports, rewrites the ones that named a sibling by bare module name, and concatenates the bodies
under a banner. Nothing inside a function body is touched. \code{--verify} compares \emph{text}:
every top-level definition's exact source, decorators included, searched for as a substring of the
module it landed in.

That verify earned itself on the first run. \code{ClassDef.lineno} is the line of the \code{class}
keyword, not of the \code{@register\_operator(...)} above it, so taking it as the start of the body
dropped the decorator off the \emph{first} class in every file: \code{cell\_geometry} silently left
the registry and 461 specs stopped loading. The counting check --- ``70 names, looks right'' --- had
passed.

\paragraph{The shims are load-bearing.} Thirty files import \code{mesh\_ops} / \code{chem\_ops} /
\code{topology\_ops} by bare module name --- \code{run\_one.py}, \code{instrument.py},
\code{vtk\_render.py}, \code{metrics.py} and twenty archive and analysis scripts --- and the campaign
is still running against them. Each moved file is a re-export, \emph{private names included}:
\code{t1\_ops} calls \code{\_carry\_face\_state} and \code{analyze\_forces} reaches for
\code{\_engine\_owns\_clock}.

\paragraph{Two operators did not come.} \code{mpm\_boundary} and \code{bm\_strain} are rejected by
\code{AUDIT.md}, and a rejection that lives only in a markdown file is one the next reader
re-promotes by accident. Their classes are \emph{cut out} of the module that moved and left in
\code{discovery\_okuda/ops/membrane\_ops.py} under a banner saying why: an archived spec that names
one still runs, and no spec can reach either from the core registry. \code{mpm\_boundary} overwrites
grid-node velocity, so the constraint is kinematic --- momentum not conserved, the reaction
discarded --- and its standoff is set by the B-spline stencil width, measured across \code{recover}
$0/2/6/20$ as $46.6\%/3.8\%/11.5\%/13.9\%$ of the sheet inside the tissue against standoffs
$+0.0006/+0.0124/+0.0088/+0.0069$, never reaching the $0 \to +0.002$ that would mean ``just
touching''. \code{integrin\_track} is the constraint it should have been. \code{bm\_strain} is, in
AUDIT's words, ``not a mechanism''.

\subsection{Redundancy: the four merge candidates, settled by reading them}

\begin{itemize}
\item \textbf{\code{interface\_tension} $+$ \code{interface\_push} --- do not merge.} They were one
  operator, \code{rd\_interface\_tension}, carrying
  $K_{\text{purse}}\sum_{\text{iface}} \ell_e \;-\; K_{\text{extrude}}\sum_{\text{red}} a\,r$. The
  first term is ordinary vertex-model physics; the second does not model a force, it pays the tissue
  to produce the morphology the campaign was searching for. One name over both cost four rounds:
  \code{K\_extrude} measured $0.0$ in all 78 specs that ever carried the operator, so nothing was
  ever forced, and the Grounder still reported a round as ``the same extrude-forced star for a
  fourth round'' on three runs whose specs contain no such operator. The split \emph{is} the fix.
\item \textbf{\code{ecm\_stress} / \code{block\_stress} --- merge, in Phase D.} Same body. They
  differ in two defaults --- \code{scale} $0.15$ for the matrix against $0.004$ for the block, which
  is right, since the block is ${\sim}130\times$ stiffer --- and in \emph{which module-level history
  list} they append to. That list is the only reason the duplicate exists.
\item \textbf{\code{ecm\_seed} / \code{block\_seed} --- do not merge.} Box-minus-a-cavity with
  aligned fibres against two slabs of jittered lattice. Same family, different geometry.
\item \textbf{\code{integrin\_adhesion} vs \code{integrin\_pull}/\code{seed}/\code{track} --- do not
  merge.} One is membrane$\to$epithelium, the other matrix$\to$membrane. The shared prefix is the
  problem, not the code; they go in one module with that sentence at the top of it.
\end{itemize}

\section{The twin-run gate}\label{sec:twin}

\paragraph{The protocol, stated exactly.} \emph{Run the spec in okuda first, and run the twin spec in
the codebase. Do not use previous okuda results --- they can be updated. Run both on the L4 cluster
node, in parallel.} Nothing already sitting in \code{log/okuda} is ever the reference: those
artefacts were produced by whatever okuda was on the day they were written, and \code{round.py} runs
campaigns into that tree while \code{staged.py} writes into it by hand. A promotion checked against a
stale file proves that the file has not changed, which is not the question.

\paragraph{What counts as identical.} The two writers differ --- okuda's \code{RunArchive} writes
\code{traj.npz} (\code{pos\_i}, \code{act\_i}), the core writes \code{trajectory.npz}
(\code{<set>\_\_pos}, \code{<set>\_\_occ}, \code{<set>\_\_chem}) --- so a file hash cannot match and
is not the test. What makes the two comparable at all is that okuda's own frames come out of
\code{engine.\_assemble}: \code{run\_one.py:593} reads \code{out["sets"]["vertex"]["pos"]} and
\code{out["sets"]["cell"]["state"]["chem"]}, the same structure the core writes. So okuda's
\code{pos\_i} \emph{is} the core's \code{vertex\_\_pos[t]} cropped to the live prefix, and
\code{act\_i} \emph{is} \code{cell\_\_chem[t][:nF,0]}. okuda keeps the ${\sim}60$ frames its movie
draws and stores their row indices in \code{ticks}; the core keeps every row; the okuda side is read
first and its \code{ticks} select the core's rows.

\paragraph{The repeatability floor is zero, and it was measured.} Byte-identity is only the right
criterion if the platform can deliver it, and over 1{,}800 frames that is not obvious: one differing
mantissa bit can move an \code{edge\_flip} decision ($\ell < \code{l\_th\_frac}\cdot\bar{\ell}$) and
from then on the two runs have \emph{different topology}, at which point ``max $|\Delta|$'' is not
small, it is meaningless. So \code{--phase R} runs the identical spec, the identical code and the
identical commit \emph{twice}, as two separate jobs. \code{b\_star} at 1{,}800 frames, growing 2{,}000
cells to 12{,}272 through division and T1: \code{beb6fb24fe86dcde} both times, $\max|\Delta| = 0.0$
exactly, no first differing bit, over 120 arrays per run. The floor is zero, so \code{tol = 0} is a
real criterion at full length and every row keeps it. A tolerance would have to be justified by a
floor above zero; there is not one.

\paragraph{Determinism is asserted, not assumed.} \code{engine.py} sets
\code{torch.use\_deterministic\_algorithms(True, warn\_only=True)}, and \code{warn\_only} silently
downgrades any kernel with no deterministic implementation --- which is exactly where two runs of one
spec stop matching. Each side runs with \code{PLEXUS\_STRICT\_DETERMINISM=1}, which turns the
downgrade into an exception, so a side that dies of it \emph{fails} rather than passing on a
comparison it never earned.

\twintable

\noindent Every row runs at its spec's own length. 100 frames was too short to test anything
structural: \code{b\_star}'s topology keeps changing past frame 800, so a 100-frame gate green-lights
a promotion that has not run one of the divisions and flips it claims to preserve.

\paragraph{Which row is the actual claim.} The \code{okuda@HEAD} vs \code{okuda} rows compare okuda
before the change to okuda after it: they prove the \emph{move} changed no bytes, which is necessary
and is not the question. The \code{B-core} rows are the claim --- \code{Plexus\_Main.py -o generate}
against \code{run\_one.py}, different runner, different recorder, different writer, the core registry
with no okuda import on one side. \code{b\_star}'s \code{B-core} digest is the same hex the
repeatability pair produced, so the core run, the okuda run and two independent repeats of the okuda
run all agree bit for bit, positions and chemistry alike.

\paragraph{Four of the rows are the minisite's death scenes}, run to their own length rather than
truncated, because a gate whose archive stops before the deformation cannot show what it claims to
test. A $45^\circ$ cap of 293 cells draws the surface \emph{inward} --- an invagination, the one
deformation growth cannot make; nine bands of 895 deaths close over every gap and the vesicle stays a
sphere at reduced volume $0.981$; 285 of 400 cells above the equator leave an ellipsoid pulled from a
sphere at \code{gyr\_prolate} $1.869$, with the topology intact. \code{apop\_many} is the only new
spec in the set, and it exists because one row moved is not the hard case for a renumber: its 200
deaths are spread along the Fibonacci spiral by a stride of 10, so \code{keep} is interleaved rather
than a contiguous block --- the case a renumber written as a truncation passes and one written as a
gather has to get right.

\section{The okuda\_ECM gates 00--04}\label{sec:gates}

\paragraph{What they were.} Not assert-scripts. \code{test\_00\_spheroid.py} writes a
\code{spec.yaml} saying what it did, a \code{metrics.json} and some plots --- it \emph{reports}. Its
``spec'' is built imperatively in Python, and its output lands wherever the script chose under
\code{log/okuda\_ECM/}. And not one of the 461 specs in \code{config/okuda/} names a single junction,
ECM, membrane or contact operator, so 34 of the operators just promoted have no declared spec at all.

\paragraph{What they become.} Two dedicated homes, and a threshold that exists before the run.

\begin{itemize}
\item \code{config/gates/} --- one yaml per gate, lifted out of the script, carrying the sets, the
  operators, the schedule, the frame count, the seed, \emph{and} the declared thresholds with their
  tier. The spec becomes the gate's definition rather than a side effect of running it, which is what
  makes a threshold auditable before the run.
\item \code{log/gates/<gate>/} --- the promoted run's outputs: \code{metrics.json}, the gate table as
  written, the plots, the movie. \code{log/okuda\_ECM/} stays as the okuda side and is not written
  over, so the two can always be diffed.
\end{itemize}

\paragraph{The tiers are the paper's, and \code{basis} is the column that keeps them honest.}
\emph{Bookkeeping} asks whether the code does what the operator says. \emph{Closed form} asks whether
the implementation reproduces the physics it was \emph{given}. \emph{Measurement} asks whether the
model agrees with something observed in cells. A threshold copied off a previous run of the same code
is none of those three --- it is a \emph{regression pin} --- and left in the measurement tier it reads
as biology. So every row also declares \code{basis: identity | analytic | reference | literature},
and the fraction at the foot of the table is reported against both.

\paragraph{And the measurement tier turns out to be available.} \code{general.units:} is declared in
\code{schema.py}, parsed through \code{plexus/units.py}, and its calibration is already on disk:
\code{log/okuda\_ECM/0u\_units/units.json} gives one tissue length unit $=10\,\mu$m and one frame
$=600$\,s. So gate~00 carries three rows in the unit of the phenomenon rather than of the mesh: a
$13.08$\,h cell cycle against the $12$--$24$\,h a cultured epithelial cell takes; a $7.66\,\mu$m cell
against $5$--$15$; a $359\,\mu$m spheroid against the $100$--$500\,\mu$m at which a real one's core
goes hypoxic and this model, which has no nutrient field, stops being about anything. Preflight
\emph{refuses} a physical row on a spec with no \code{units:} block, and refuses any \code{unit:}
string that names the mesh --- ``$0.82$ grid cells'' sounds small and is $15\,\mu$m.

\paragraph{Gate 00 was reconstructed, and that was the hard part.} \code{test\_00\_spheroid.py} does
not run a tissue, it \emph{loads} one, so the model had to be recovered from the cache's provenance.
Two candidate parents exist and they are \emph{different models}: the pre-basis
\code{cellfix\_B\_new.yaml} says \code{rate: 0.003457} and is what the cache was built from, while
the \code{\_archive\_runs} copy \code{tissue.py} falls back to today says \code{rate: 0.03} and
reaches $1{,}451$ cells by frame $60$ against the cache's $227$. Gating against the wrong parent
would fail a correct run. The reconstruction is confirmed by the run itself: $6{,}914$ cells exactly,
apical-radius fold $3.86064$ against the cache's $3.8607$, aspect $1.01931$ against $1.0193$.

\paragraph{Its first run failed five rows and four of them were the measuring code}, which is what a
gate is for. \code{apical\_radius} was a mean where the reference is a median; \code{aspect\_ratio}
was a gyration tensor where the reference is a percentile pair; \code{mean\_cell\_diameter} fanned
its triangles from the body's centroid instead of each face's and read $50.9\,\mu$m for a cell that
is $7.66$; and \code{t1\_total} reconstructed the count as ``new edges minus three per new face'',
which is wrong because a division \emph{splits} two edges --- five pairs appear and two vanish --- so
it read $16{,}169$ against $1{,}499$. Excluding divisions by geometry instead of by arithmetic gave
$2{,}890$, still not $1{,}499$, because a 3D reversible network reconnection rewires more than the
one edge it is named for. Two numbers each right about a different quantity is the worst kind of
disagreement: neither side is wrong and the row is meaningless. So the engine now records the
operators' own counters --- \code{MeshTable.SCALAR\_RECORD}: \code{n\_t1}, \code{n\_apop},
\code{div\_blocked}, \code{apop\_spill} --- and the row reads $1{,}499$.

\paragraph{And gate 01's did the same thing twice, which is the point of having them.}
Myosin is the hard case for this promotion because it is the only state in the model that lives on a
\emph{relation} rather than on a body: its array is indexed by half-edge, it is written before the
frame's topology operators rewire that index, and \code{junction\_sync} has to re-key it afterwards.
On the archived 401-frame run, 56 of 200 snapshots carried a myosin array 6 to 1{,}356 entries short
of the edge arrays --- and every reader indexes it positionally, so each of those frames coloured,
averaged and thresholded the wrong junctions. The gate asserts the alignment on the belted arm
($0$) and reports it on the arm with the re-keying removed ($2{,}106$), so the check has a positive
control rather than only a green light. \code{junction\_sync} itself is asserted
\emph{trajectory-neutral at exactly zero} --- not ``small'' --- because it writes only
\code{m["myo"]} and nothing reads it before the tick ends; the measured maximum vertex displacement
between the two arms is $0.0$.

Two of its rows failed on the first grading and both were the threshold. \code{t1\_rate} had been
derived by dividing $1{,}499$ exchanges by the \emph{final} cell count instead of the mean over the
run --- the tissue spends most of its frames small --- and read $0.00215$ against a demand for
$0.00105$; the archive says $0.002206$, so the measurement was right to $2\%$ and the arithmetic
behind the threshold was not. And \code{hot\_junction\_fraction} asked for at least $2\%$ of
junctions above $1.5\times$ the mean while its own sibling asserted $p_{98}/\text{mean} \ge 1.20$:
those are not two checks, they are a contradiction, since $p_{98} = 1.42$ means exactly $2\%$ lie
above $1.42$ and so at most $2\%$ can lie above $1.5$. A row that cannot pass while its neighbour
passes is not strict, it is wrong. It was replaced by one that is independent --- the correlation
between a junction's myosin and its length, which separates a length-keyed belt from a tension-keyed
one where the dispersion cannot, because both keyings raise the dispersion identically.

\paragraph{And that replacement failed too, with the sign backwards.} I asserted $r < -0.10$,
reasoning that a belt contracts short junctions. It measured $+0.639$. The operator's own comment
settles it: \emph{``length-keyed, $+$: longer $\to$ more myosin $\to$ shorter. Negative feedback on
length''} --- the target is $a\,(1 + \beta(\ell/\bar{\ell} - 1))$, linear and increasing in $\ell$,
so the correlation must be positive, and it is below $+1$ only because the myosin relaxes toward that
target over 20 frames. The same comment warns that ``getting this backwards silently converts the
experiment into its own control, so it is written out rather than inferred'', which is precisely what
a threshold reasoned from intuition rather than from the update rule did here. The row is
\code{basis: analytic} now, because the sign follows from the rule and needs no previous run.

\paragraph{Gate 04's replay input is regenerated, which is as far as ``never replay'' can go here.}
The rule cannot mean solving both subsystems in one schedule: the tissue's clock is $600$\,s a frame
and the matrix's is $3.2$\,ms, a ratio of about $10^5$, so a live coupling would need on the order of
$100{,}000$ matrix frames per tissue frame. What it does reach is the \emph{input}, and there it
changed everything --- gate 04 read a 32.7\,MB npz built in August, uncommitted, whose parent spec no
longer resolves (\code{tissue.CELL\_SPEC} now gives \code{rate: 0.03} against the \code{0.003457}
that made it). \code{config/gates/gate\_04\_tissue.yaml} is that pass declared, and
\code{tools/export\_tissue.py} writes its recorded surface into the layout \code{mesh\_contact}
consumes. The regeneration is exact --- $200 \to 6{,}380$ cells, median radius
$4.6622 \to 17.5848$, every per-mesh key including \code{myo\_med} --- which is how we know the
declared spec is the one that built the cache. It works only because the engine's recorder is now a
\emph{superset} of what the cache carried: \code{FACE\_RECORD}, \code{EDGE\_RECORD} and the
operators' own counters.

\paragraph{And gate 04 is red on one row, declared red rather than widened.} A prescribed surface
makes non-penetration \emph{analytic}: the tissue's radius is known per frame, so ``no matrix inside
the epithelium'' is exactly $\min |p - c| \ge$ that radius, needing no stress, no contact counter and
no module global. The nearest material point ends at $0.1354$ of the box against a prescribed
$0.150$. As a fraction that is $0.0146$ and reads as a rounding error. In micrometres it is
$17.1\,\mu$m against an epithelial cell diameter of $8.6$ --- the matrix indents the tissue by two
cell bodies. This is the paper's own worked example of why the measurement tier needs a
\code{units:} block, and the same quantity was once reported as ``$0.82$ grid cells'', sounded small,
and was described as an improvement. What would fix it is not a threshold: \code{mesh\_contact} is a
penalty, a force proportional to depth, so a steady load always produces a steady overlap, and
\code{k\_frac} is already at $0.15$ of the explicit stability ceiling. A barrier formulation removes
the overlap by construction --- a change to the operator, in its own commit, with its own twin run.

\paragraph{And the gates are twinned against okuda, not only against their own thresholds.}
A gate grades the CORE against numbers a human wrote down; that is worth having and it does not say
core and okuda agree. \code{--phase G} runs every lifted gate spec through both runners, fresh and in
parallel, and \code{--phase REP} does the same for three specs the CAMPAIGN wrote --- 14 to 15
operators apiece, emitted by \code{round.py} from its own search. A promotion that reproduces its own
test set and not the corpus it was built from has reproduced the tests. Nineteen twin rows on record,
nineteen identical.

Two of the six gate rows compare core against core across a commit rather than against okuda, and
that is a fact about okuda's runner: \code{run\_one.py} reads \code{H.level("vertex")} in three
places, so a mesh-free spec dies with \code{KeyError: 'vertex'} before frame 0. okuda is a mesh
harness and gates 02 and 04-pass-2 are pure MPM. The rows are labelled as regression checks rather
than dressed up as agreement.

\paragraph{One row came back DIFFER and the model was right.} \code{r023\_07} --- the only one of the
three with \code{cell\_die}, whose \code{stalled} selector is a float threshold and therefore exactly
where a last-bit difference would become a one-cell difference --- reported
\code{act\_20: shape (2529,) vs (2530,)}. Reading the core trajectory at okuda's own ticks gives
\code{nF} identical at every recorded row. The fault was the comparison's crop: okuda slices
\code{chemf[t][:nF]} and the bridge sliced by \code{cell\_\_occ[t].sum()}, which are the same number
except around a death. It crops by the mesh now.

The one-cell gap is real and is recorded rather than waved away: \code{cell\_\_occ.sum()} leads
\code{nF} by exactly one on 23 of 1{,}801 rows, always at a death, never by more, while
\code{vertex\_\_occ.sum()} matches \code{Nv} on all 1{,}801. Gate 00 carries that check and passes
it, because gate 00 has no death operator and never reaches the path --- a green row on a spec that
cannot exercise it is not evidence.

\paragraph{And that run is half NaN, and its own diagnostics say so and pass it.}
\code{r023\_07}'s activator goes non-finite at frame 889 and stays there: 2{,}995 of 2{,}995 cells,
on both sides of the twin. The campaign's \code{diag.json} records \code{act\_extinct\_frame: 889}
and \code{act\_max\_final: nan} and stamps \code{valid\_evidence: True} anyway, because the validity
check asks whether operators ACTED, not whether the state stayed finite. The VTK renderer says it
without being asked --- magenta means ``not a cell any more'' and the final frame is solid magenta.
A \code{no\_nan} row of the kind gates 00, 02 and 04 carry would have failed it at frame 889.
