Optimization

Differentiable design — tuning a foraging colony end-to-end

And because a Plexus design is just a spec — a handful of numbers over a fixed operator set — that design can be optimized, not only simulated. The forager here is a colony of deformable cells: each cell is a soft elastic body simulated with MPM (the material-point method), and the colony navigates by chemotaxis — sensing an attractant gradient that points toward the food and climbing it — coordinated by boids flocking, with MPM handling the physical push against walls and neighbours. A black-box UCB search tunes the spec’s parameters — motility speed and turn rate, sensing gain, material stiffness (youngs), cell size and count, and the four boids weights — from a hand-set design (left) to the best found (right), which delivers food roughly five-fold faster.

Harder navigation

The same recipe scales to harder navigation — a porous pillar field and a walled maze, each crossed by climbing a food-attractant gradient that itself flows around the obstacles, and tuned by the same optimizer. Each strip runs left → right, from its starting point to the optimized colony.

Maze — a walled labyrinth

The colony never “sees” the maze — it only reads a local food-attractant gradient — yet the optimizer discovers spec parameters that route the population through the labyrinth. Same operators, same engine; only the spec changed.
